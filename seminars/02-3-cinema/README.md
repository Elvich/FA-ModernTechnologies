# Семинар 2-3. Кинотеатр

Вариант А–Е (фамилия на «Г»): поле киностудии `studio`, сортировка по дате и времени сеанса по возрастанию, гистограмма за 7 календарных дней, включая сегодня. По уточнению пользователя приложение **без авторизации**.

## Запуск

Команды выполняются из корня репозитория. Требуется Java 17+; Maven загружает корневой Maven Wrapper.

Для MySQL создайте базу `cinema` с кодировкой `utf8mb4` и пользователя с правами на неё. Укажите свои настройки:

```sh
export DB_URL='jdbc:mysql://localhost:3306/cinema?serverTimezone=Europe/Moscow'
export DB_USER=fa
export DB_PASSWORD='ваш-пароль'
./mvnw -pl seminars/02-3-cinema spring-boot:run
```

Откройте <http://localhost:8083>. Порт можно заменить переменной `PORT`. Таблица `screenings` создаётся ORM автоматически. MySQL сохраняет данные между запусками.

Для знакомства без MySQL:

```sh
./mvnw -pl seminars/02-3-cinema spring-boot:run -Dspring-boot.run.profiles=demo
```

Профиль `demo` использует временную H2 в памяти: после остановки данные удаляются. Это дополнительный режим, основная БД по заданию - MySQL.

## Возможности и поля

- Добавление, просмотр, редактирование и удаление сеансов.
- Поиск без учёта регистра по ID, фильму, студии, ISO-дате/времени, числу билетов. Один запрос ищет подстроку в совокупности полей.
- Сортировка по дате сеанса (возрастание по умолчанию или убывание); при одинаковой дате - по ID.
- Счётчик записей, показанных в таблице после поиска.
- Гистограмма всех сеансов за сегодня и шесть предыдущих дней с нулевыми днями. Поиск таблицы не меняет гистограмму.

| Поле | Значение |
| --- | --- |
| `id` | Автоматический ID |
| `filmTitle` | Название фильма, обязательно, до 200 символов |
| `studio` | Киностудия, обязательно, до 200 символов |
| `startsAt` | Местные дата и время сеанса, например `2026-11-04T18:30:00` |
| `ticketCapacity` | Всего билетов, целое неотрицательное число |
| `soldTickets` | Продано билетов, от 0 до `ticketCapacity` |

Местные даты не конвертируются между часовыми поясами. «Сегодня» определяется часовым поясом сервера JVM. На форме доступны секунды. Поля валидируются и в браузере, и сервером; проданных билетов не может быть больше общего числа.

## REST API

| Метод | Адрес | Результат |
| --- | --- | --- |
| GET | `/api/screenings?q=...&direction=asc` | Список, поиск и сортировка (`asc` / `desc`) |
| GET | `/api/screenings/{id}` | Сеанс, либо 404 |
| POST | `/api/screenings` | Создать, 201 и `Location` |
| PUT | `/api/screenings/{id}` | Полностью обновить существующий сеанс |
| DELETE | `/api/screenings/{id}` | Удалить, 204 |
| GET | `/api/screenings/histogram` | Семь объектов `{date,count}` от ранней даты к поздней |

Тело POST/PUT:

```json
{"filmTitle":"Солярис","studio":"Мосфильм","startsAt":"2026-11-04T18:30:00","ticketCapacity":100,"soldTickets":25}
```

Ошибки формата/валидации возвращают 400 и JSON с `message`; отсутствующий сеанс - 404. Данные пользователя выводятся через `textContent`, без вставки HTML. Внешние CDN не используются.

## Проверки

```sh
./mvnw -pl seminars/02-3-cinema test
```

HTTP-интеграционные тесты с настоящим Spring-контекстом, ORM и H2 (`MODE=MySQL`) проверяют CRUD, поиск и оба порядка сортировки, ограничения билетов, некорректные даты, 404 и гистограмму на границах семидневного интервала. Для повторяемости тестов время фиксировано. H2-тесты не заменяют проверку с MySQL.
